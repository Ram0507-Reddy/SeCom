TECHNICAL DOCUMENTATION

Guide and cryptographic pipeline specifications for SeCom.

01 / How It Works Guide

SeCom enables instant end-to-end encrypted messaging with a strict 15-second self-destruct countdown. To start a secure session, follow these steps:

  1. Generate Keys: Enter a temporary nickname to initialize. Your browser immediately generates a local 256-bit ECDH key pair in RAM.
  2. Open Channel: Click "Generate New Channel" to create a randomized 6-digit room, or connect to a room code shared by your peer.
  3. Exchange Credentials: Once both users are active in the room, public keys are automatically synced. A shared AES-GCM-256 symmetric key is derived in memory.
  4. Encrypted Chat: Write a message. Payloads are encrypted client-side using the derived key. Deletion occurs 15 seconds after recipient decryption.

02 / Cryptographic Architecture

SeCom relies entirely on client-side encryption sandbox protocols to ensure your keys and plaintexts never traverse the network:

Security Layer Standard Purpose
Key Exchange ECDH P-256 Generates ephemeral shared secret key pairs in browser RAM.
Symmetric Encryption AES-GCM-256 Encrypts message payloads using unique 12-byte initialization vectors.
Key Derivation HKDF (SHA-256) Derives strong symmetric cipher keys from ECDH bits.
Transit Storage Cloud Firestore Holds ciphertext transiently. TTL-enforced document deletion triggers 15s after read.

03 / System Requirements

SeCom uses native browser cryptography libraries. No downloads or plugins are required. Compatible with:

  • Google Chrome 80+ / Chromium-based browsers
  • Mozilla Firefox 75+
  • Apple Safari 14+
  • Microsoft Edge 80+
