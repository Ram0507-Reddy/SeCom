FREQUENTLY ASKED QUESTIONS

Security, operational, and architectural answers.

How does the 15-second self-destruct mechanism work?

When a recipient decrypts a message, a Firestore timestamp update registers decryptedAt. The client listens to this update and starts a 15-second timer. When the countdown expires, the client triggers a Firestore document delete query, destroying the record. If the recipient tries to reload or disconnect mid-timer, the security rules block subsequent reads, and the next client immediately deletes the stale document.

Are messages readable by Google, Firestore, or administrators?

No. All encryption occurs client-side in the browser using the Web Crypto API before the payload leaves your sandbox. Private key buffers are derived dynamically and stored strictly in active browser RAM (never saved to local storage or transmitted to any server). Because the server only sees AES-GCM-256 ciphertext and random IV buffers, administrators have no way to decrypt your chats.

Do I need to sign up or input my email/phone number?

No. SeCom is built for total anonymity. No registration, emails, phone numbers, or profiling details are requested. In the background, Firebase Anonymous Auth generates credentials purely to comply with Firestore database access policies without collecting any personal data.

What happens if my chat contact leaves the session?

When a peer clicks "Disconnect" or closes their browser tab, their session registration is deleted from Firestore and their private in-memory key is cleared. The active channel immediately resets, disabling message sending and clearing all pending messages automatically.
